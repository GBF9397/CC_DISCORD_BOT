# 问题踩坑复利

已解决（归档）的问题，按版本分，每条写：问题 → 原因 → 怎么修的。
- 新会话：通读一次。之后只看新加的条目，或者遇到类似问题（developer 提到或提醒）时回来查。
- 解决了新问题就加在对应版本最后；同一类问题又出现，就在原条目下补一行「再次出现：…」。
- 还没解决的问题不放这里，放 `目前进度.md`。
- 版本划分（已用 Discord 公告核对）：v1.0 = 10-05 基础聊天；v1.1 = PR #1～#3；v1.2 = PR #4～#8；v1.3 = PR #9～#11；v1.4 = PR #12～#22 + 分支 `claude/task-nb5ft9`。

## 通用（每个版本都可能再遇到）
- **测试结果来自旧代码** → developer 在 `main` 上测了半小时，修复其实在分支上 → 每次测之前让 developer 跑 `git log --oneline -1`，对一下 commit id。
- **log 丢了** → `Start-Process ... -RedirectStandardError bot-error.log` 每次启动都会覆盖 log → 重启**之前**先读 log。
- **以为开了两个 bot** → `Get-Process python` 显示 4 个进程 → 一个 bot = bot + 监控窗口，各自是 venv 小启动器 + 真正的 python；ComfyUI 会再多几个，两个 bot 才是 8 个。
- **合并显示 "Already up to date"，main 却没变**（10-09）→ 在 main 上 `git pull` 只会下载分支的新提交到 `origin/claude/task-nb5ft9`，本地的 `claude/task-nb5ft9` 还是旧的；`git merge claude/task-nb5ft9` 合的是本地旧分支 → 合并时用 `git merge origin/claude/task-nb5ft9`，合并完对一下 `git log --oneline -1`。
- **分支落后 main** → 其他会话也在推 → 告诉 developer 分支可以合并之前，先把 main 合进分支。
- **Discord 限制**：不显示 markdown 表格（用列表写）；下拉菜单最多 25 个选项；按钮点击要在 3 秒内回应（先 defer）；打字的消息不能弹表单（要放一个按钮）；公开的 @ 一定会被看到；只有斜杠指令才有"只有你看得到"的消息。
- **云端会话不能跑 bot** → 没有 GPU 和 LM Studio，DuckDuckGo 被代理挡掉 → 云端只跑单元测试（`python -m pytest`，用假的 LM Studio）。
- **云端会话联系不到 developer 本地的会话** → 交接靠文件，developer 手动带过去。

## v1.0（10-05 基础聊天）
- **不知道 bot 有没有看到频道** → 启动时记录能不能看到 `BOT_CHANNEL_ID` 的频道，每条消息记录频道、作者、字数（不记内容）。
- **bot 自己的 log 不显示** → 设置 logger。
- **`pythonw.exe` 启动没反应** → 改用 `Start-Process .venv\Scripts\python.exe bot.py -WindowStyle Hidden -RedirectStandardError bot-error.log`。
- **venv activate 被挡** → `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`。
- **改了 `.env` 没生效** → `.env` 只在启动时读 → 改完要重启。`BOT_CHANNEL_ID` 写一行、逗号分隔；有第二行的话会覆盖第一行。

## v1.1（PR #1～#3：看图、上网搜索、人设）
- **模型说自己不能上网** → 告诉模型它拿到的是实时搜索结果。
- **回复是空的或被截断** → Gemma 会先推理 → max_tokens ≥ 512，只读 `message.content`；LM Studio 的上下文长度要 16384 以上。

## v1.2（PR #4～#8：角色人设、表情和贴纸、30 条记忆、unfiltered）
- **贴纸发太多** → 默认关闭，`.env` 写 `STICKERS=on` 才开。
- **表情乱用** → 每个表情/贴纸先给 Gemma 看图学意思，再参考成员最近两次怎么用（都只在 RAM）；`emoji_meanings.txt` 可以手写意思。

## v1.3（PR #9～#11：画图、随机回复长度、表情修复）
- **显卡 16GB 放不下 Gemma 和 ComfyUI** → 轮流用：`lms unload` → ComfyUI 画图 → `lms load`。
- **图片被存到硬盘** → 改成从 ComfyUI 的 websocket 直接拿图，也不留在 ComfyUI 的历史里。
- **Gemma 说自己不会画图** → 告诉它成员可以用 `!draw`。
- **refine 丢掉没写进提示词的细节** → refine 时让 Gemma 看上一张图。
- **新角色细节不准**（例如 `!draw zenless zone zero claret` 少了大镰刀）→ 画图模型只认识 2025 年以前的角色，查到的图也可能混进同作品的其他角色 → 这是模型本身的限制，不是 bug；公告里先讲清楚，让成员用 `!refine` 修。
- **有名的角色画错** → 写提示词前先上网查（文字 + 最多 5 张图），只用跟文字对得上的图。
- **新角色（2025 以后的）被画成同系列的别人** → 画图模型不认识新角色 → 不写名字和作品，只描述长相。
- **log 里出现搜索词** → 静音 `ddgs`、`primp`、`httpx` 的 logger。
- **搜索的回答被长度上限截断** → `/search` `!search` 不受长度上限限制。
- **表情没显示**（Gemma 少写冒号、写全角 `：name：`、紧贴中文）→ 自动转成真正的表情。

## v1.4（PR #12～#22 + 分支 `claude/task-nb5ft9`）
### 角色扮演（人设）
- **口头禅说个不停、重复同一句**（developer 的建议）→ 最初的设定鼓励把口头禅写进笔记，Gemma 就每句都用 → 口头禅只当调味料，偶尔用一次，不重复最近几次回复里用过的词，回应对方实际说的或发的图。
- **角色搞混**（把同作品的别人当成他）→ Gemma 凭记忆写人设 → 优先用网上资料；被问"是谁 / 叫什么 / 在哪里"时先上网查；每 8 条消息重新确认一次角色是谁。
- **态度只有一种**（宿傩对谁都瞧不起）→ 最初只写"几个关键关系"，没写对强弱的态度 → 笔记要写对弱者和对值得尊重的对手各是什么态度，跟原作走：瞧不起弱者，但认可跟得上的对手。
- **聊到战斗只会喊招式名** → 最初没写能力 → 多搜一次能力和招式；像原作一样冷静讲规则，也拆解对方的招式（例如宿傩分析五条悟的术式）。
- **名字和外语词怪**（罗马拼音 mousou、英文名）→ 写成中文，人名、地名用官方中文译名，括号附英文。
- **看到图乱认人、嘲笑角色本人、说套话** → 先看图里实际有什么（远景近景、表情、姿势、图上的字）；认不出是谁就不猜；永远不嘲笑角色本人。

### 聊天 / 工具
- **log 里又出现搜索词** → 子 logger `ddgs.ddgs` 没被静音；`disabled=True` 管不到子 logger → 用 `setLevel`。
- **回复被硬切成「…」** → 太长时请 Gemma 在长度上限内重写，不直接截断。
- **`/event` 失败但看不到原因** → 先 defer，再把 Discord 的错误信息显示出来。
- **粘贴的 `/event ...` 没反应** → Discord 把它当普通文字发出 → 当文字指令解析（所有指令都支持 `!` `！` 和粘贴的 `/`）。
- **投票默认开 32 天太久** → 没 @ 人开 1 天，@ 了人开 7 天。
- **「结束活动」按钮超时**（Discord 报错 3 秒）→ 先回应点击，再结束活动；活动已经结束时再点（错误 180000）→ 只把按钮拿掉。
- **`!comment` 开头带 @ 或换行时认不出** → `text_command()` 处理不了这种情况 → 在它之前先用 `COMMENT` 正则匹配。
- **`/persona` 没有 `!` 写法**（违反硬规则 1）→ 加 `!persona`，跟 `/persona` 共用 `switch_persona()`。
- **`!recall` 改成撤回后，斜杠指令说明还写着旧行为** → 改功能时要连指令说明一起检查。

### 画图
- **imagegen 里调用 `core.X` 卡死测试** → imagegen 有个叫 `core()` 的函数 → 模块写成 `import core as brain_core`。
- **测试用的假图片让 `shrink` 崩溃** → 读不了的数据直接原样传过去。
- **大图上传超时**（重试 3 次 × 2 分钟）→ 用 Pillow 缩到最长边 1024，Gemma 只给一次 5 分钟，通知里倒数。
- **LM Studio 回 400 "'url' field must be a base64 encoded image"** → LM Studio 读不了 WebP → 所有给 Gemma 看的图都经过 `core.image_part()` 转成 PNG。
- **refine 改动太小**（small 只重画 45%）→ developer 的规则：提到的改动至少重画一半 → small 0.55；发色算 big（0.75）。
- **几轮 refine 后之前的改动被冲淡** → developer 的规则：没提到的保持原样 → 没提到的 tag 保留原文和权重，只有这轮新加的 tag 加 1.3 权重。
- **改了角色平时的样子（例如红发甘雨）却画回原样** → 画图模型看到名字就画原样 → 不写名字和作品，只描述长相，至少算 big。
- **换发色失败**（官方甘雨图改红发）：重画 75% → 红发但角变猫耳、姿势跑掉；60% + 褪色 → 白发带红挑染、像另一个人 → 最终方案：ControlNet canny（跟线稿，强度 0.8，用到 80% 步数），重画 90%（`SD_CONTROLNET`）。PC 上通过。
- **换角色变成普通的青发女生** → 名字被去掉 + 图被褪色 → 换角色保留名字，而且永远不褪色（`SWAP_NOTE`）。
- **撤回后 refine 一直出同一张不想要的图** → 撤回没真的删掉，refine 又用同一个 seed → `!recall` 改成真正的撤回（删掉最新一张），之后的 refine 换新 seed。
- **多张角色图只读了第 2 张**（结果浅青发、红眼、没角）→ 最多读 3 张角色图；角色名和特征放最前面加 1.3 权重，第 1 张原本的发色/眼睛放进"不要画"；换角色也用 ControlNet，但比较松（0.5，用到 60%），重画 90%。
- **提示词示例刚好是甘雨的特征，可能把别的角色带偏**（乱加角）→ 示例改成中性写法，并写明只写角色真正有的特征。

### 私人画图（`!dm…`）
- **`!dmdraw` 的消息没被删掉** → bot 在那个频道没有「管理消息」权限 → developer 给了权限；删不掉时 bot 会私信告诉成员（`CANT_HIDE`）。
- **关了私信 bot 还是能私信到** → 「允许服务器成员私信」是每个服务器分开的开关 → 跟 bot 同在的每个服务器都要关；这是 Discord 的规则，不是 bug。
- **公告里不写管理员设置**（权限、私信开关、`.env`）→ 只有 developer 是管理员，他自己处理。
