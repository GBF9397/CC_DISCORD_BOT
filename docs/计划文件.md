## 长期目标（Ep，10-09）
- 【】**画图达到大模型（例如 Gemini）的水准**：稳定性、准确度、画风变化、内容库（认识的角色和东西）四项都到那个标准，才算达成。
  - 现实差距：Gemini 是云端大模型；我们是本地 SDXL + Gemma 12B + 16GB 显卡。要一步步逼近，每一步都要在这台电脑上跑得动。
  - 可以拆成的小步（Ep 选了才做）：
    - 【】稳定性：同一个请求画几次，结果都像样（固定质量词、负面提示词、失败自动重画）
    - 【】准确度：说什么画什么（局部重画 inpainting、更多 ControlNet、提示词检查）
    - 【】画风变化：多几种画风模型或 LoRA（`SD_STYLES`）
    - 【】内容库：认识更多角色（角色 LoRA、IP-Adapter 参考图）
    - 【】换更新的本地模型（例如 Flux 这类），要先确认 16GB 显卡跑得动、速度能接受
  - **检查点（Ep，10-09）**：用这 7 点看离目标还有多远。要做时 Ep 一次挑一个，做完、测完再挑下一个，不要一次做完。能量化的就记数字（只记次数和时间，不记内容，硬规则 2）。
    1. 【】要写的提示词越来越短、越来越少，图还是稳定准确 → 记：每张图的请求字数
    2. 【】refine 轮数越来越少，几次就达到要求 → 记：从 draw 到最后一张的 refine 次数、撤回次数
    3. 【】分得清越来越复杂的图，改得动越来越难察觉的部分 → 用一组难题图定期重测。题库要越加越多、越来越多样（不同角色、画风、构图、改动类型），这样模型不会只针对一两种题目调好。
       - 题库（之后每遇到新难题就加一条）：
         - 甘雨官方图 → `/edit 把头发改成红色`（大面积换颜色，角和姿势要保留）
         - 女仆图 + 2 张甘雨 → `!dmedit 第2和第3张的角色穿第1张的衣服`（多张图换角色）
         - 女仆图 + 没有角的角色 → 换装（不能乱加角，测试清单 #17）
         - 女仆图 + 冷门或自创角色 → 换装（配色要跟过去，测试清单 #18）
    4. 【】图片尺寸和比例可以变，或让成员选，在速度和显卡负担之间平衡 → 记：每种尺寸的出图时间
    5. 【】PC 上有没有别的程序在抢显卡（游戏、浏览器、视频、其他 AI 工具等），影响出图效率 → 记：画图时显卡被谁占用、占多少显存（`nvidia-smi` 可以列出每个程序），以及出图时间有没有因此变慢；监控窗口和 `/status` 已经有显卡总占用
    6. 【】监控让图跑偏的因素和改动权重 → 记：每次的 SIZE、重画比例、用了 ControlNet 没有（log 已经有一部分）
       - 现在的数值（重画 55/60/75/90%、新加 tag 权重 1.3、ControlNet 0.8 和 0.5 等）只是按目前测过的图调出来的，不算完全正确；更复杂的图会让它们失准。
       - 后期要一边遇到新图一边慢慢调；每次调整都记进 `问题踩坑复利.md`（哪张图、原本的数值、改成多少、为什么），配合第 3 点的题库重测，确认旧题没有变差。

- 【】**角色卡 + 好感度玩法**（Ep，10-09，大型任务，长期目标；Ep 开口才做）
  - 想法：像 AI 角色卡，每个角色一套玩法；成员跟角色聊天，按回答累积好感度。角色越加越多，一张一张写。
  - 格式参考：Ep 的 skill `ganyu-galgame`（甘雨）。一张卡包含：
    - 生效规则、语言风格、好感度怎么显示（每 3～5 轮显示一次 ❤️×1～5）
    - 自称和称谓规则、输出格式（动作/神态 → 『台词』 →（内心独白 + 颜文字））、禁止 OOC 和被问是不是 AI 时怎么回
    - 角色资料、性格、多身份关系网
    - 好感度系统：5 个等级、加分和扣分的触发条件、闹别扭 / 冷战 / 和好、每个等级的对话表、内心独白场景库、物理互动反馈、追加设定
  - 入口指令名：到想法落地时再定（要有 `/` 和 `!` 两种写法，记进 `docs/指令.md`）。
  - **难点，要谨慎设计**：
    - 判断一句话该不该加好感，对 Gemma 12B 很难；连 GPT 这类大模型也会判错、重复句子。
    - 可能的方向（落地时再定）：加减分只能在小范围内（例如每句 -2～+2），一部分用固定规则判断（道歉、称呼、送礼等关键词），模型只做辅助；设冷却，防止刷分；互动路线先设计好，不全靠模型临场发挥。
  - **开始前要 Ep 决定的**：
    - 【/】好感度存在哪：Ep 10-09 同意**只为这个玩法破例**，在本地放一个专门的后台文件夹（文本文件），里面两种文件：
      - 好感度记录：成员 ID、角色、分数、等级、状态（例如正在闹别扭）
      - 角色记忆：同一个文件夹里，每个角色另外一个文件，模型自己写入、只给这个玩法用，保证不忘记、不答错（例如这个成员叫她什么、上次为什么吵架）
    - 落地时还要跟 Ep 确认的边界：记忆只写简短事实，不存原话；文件夹 gitignore，路径写在 `.env`；成员能不能看或清除自己的记录；记忆文件太长时怎么精简。做好时把这个例外写进 `AGENTS.md` 的硬规则 2。
    - 恋爱向内容不能用在未成年或看起来像未成年的角色上（硬规则 6）；每张卡写之前先确认。
    - 跟现有的 `/persona character` 是什么关系（另一个指令，还是 persona 的进阶模式）。
